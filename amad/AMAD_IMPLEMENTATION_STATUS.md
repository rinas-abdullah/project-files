## 0. Starting point (audit result)
- The repository contained **no AMAD or RASD application code** and no prior status file. It holds an unrelated
  Next.js site (Dithar) at the root, `hemo-guard-x/`, `rinas-abdullah-portfolio/` (which only *describes* "Rasd Cyber"),
  and unrelated branches (Risaq, NAJA, …). The owner confirmed AMAD had not been built.
- Therefore nothing was rebuilt or overwritten: AMAD was created as a new self-contained app in `amad/`.
  The root Dithar app and every other folder were left untouched.
- The RASD concept (adaptive adversary, live pressure, forensics, readiness, incident→scenario loop) was taken
  from the product brief and the portfolio description and preserved.

## 1. Feature implemented in this iteration
**The first complete, verified, end-to-end AMAD learning loop** (highest-priority dependency for every other
feature): authenticated user → Command Center → start simulation → adaptive adversary (guardian-validated)
→ live defensive actions under simulated time pressure → containment / breach / timeout → forensics
investigation → server-side readiness scoring → behavioral profile update → persisted next-training
recommendation → next simulation calibrated by the updated profile.

### Defects found and fixed during verification
1. Turbopack inferred the parent repo as root and loaded the parent's PostCSS config → build failed. Fixed: `turbopack.root` pinned.
2. Login rate limit counted per-IP failures at the per-account threshold (5) → a few typos behind a shared NAT would lock everyone out. Fixed: 5/account, 20/IP; regression test added.
3. Pre-emptive firewall blocks of the attacker's IP were not credited as effective (only blocks after C2 existed were) → better decisions scored worse. Fixed; regression test added.
4. "Mark all read" used `revalidatePath`; switched to Next 16 `refresh()` per the Next 16 docs.
5. Command Center told learners with history "you have no history yet" when no open recommendation existed. Fixed; E2E assertion added.
6. Command Center event feed included adversary moves (leaked hidden activity during live sessions). Removed.

no email verification / password reset / MFA; no invitations; no admin panel; no external security assessment.

## 8. Remaining limitations
- 3 hand-authored scenarios (web shell / spear-phishing / ransomware precursor); no scenario authoring UI.
- Adversary is deterministic-adaptive, not LLM-driven.
- Twin state lives inside session state JSON (no separate CyberTwinAsset table).
- Members can only be added to an organization via DB/seed (no invitation flow).
- Arabic UI only.
